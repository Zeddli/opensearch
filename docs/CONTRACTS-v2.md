# Contracts v2 — OpenQuote: real data only, per-user AI keys

Overrides CONTRACTS.md where they differ. Product name is **OpenQuote**.

## Goals
1. **No fabricated data anywhere.** Everything comes from real users' actions. No placeholder accounts, no pre-loaded seller personas/products, no fake market listings, no fake or no-money payment mode, no fake Shopify store, no rule-based stand-in agents. Delete those code paths (don't just hide them).
2. **AI key is per user, configured in Settings**, never in env or code. Remove `ANTHROPIC_API_KEY` from env.ts / .env.example / code.
3. Platform credentials (PayPal sandbox app, Channel3) stay in env — they belong to the platform operator, not to users. If missing, the feature is **disabled with a clear message**, never faked.

## Per-user AI key  [owner: BACKEND]
- Schema: add table `user_ai_settings`: user_id (pk, fk users cascade), provider text default 'anthropic', base_url text null, api_key_enc text not null, key_last4 text, model text null, updated_at. Generate migration with `npm run db:generate`.
- `src/lib/secrets.ts`: `encryptSecret(plain)`, `decryptSecret(enc)` — AES-256-GCM, key = sha256(env `APP_ENCRYPTION_KEY`). In production refuse to start crypto with the default dev value. Shopify token encryption should reuse this (replace SHOPIFY_TOKEN_ENC_KEY with APP_ENCRYPTION_KEY).
- `src/agents/llm.ts`: `getUserModel(userId, purpose: 'buyer'|'seller')` → AI SDK model from that user's provider config (Anthropic or OpenAI-compatible); throws `MissingAiKeyError` if none. Default models: buyer `claude-sonnet-5-5`, seller `claude-haiku-5-5`; user may override `model`.
- Routes: `GET /api/settings/ai → {configured, provider, baseUrl, model, last4, defaultModel, models}` (never the key); `PUT /api/settings/ai {provider?, apiKey?, model?, baseUrl?}` → validate with a minimal real call, then store; `DELETE /api/settings/ai`. PUT errors (400): 401/403 → "Invalid API key", 404 → "Model or endpoint not found", network failure → "Could not reach the endpoint"; 5xx → 502; 429 (rate limited, key accepted) → saved anyway. Omitting `apiKey` reuses the stored key when provider and base URL are unchanged.
- **Providers** (`user_ai_settings.provider`): `'anthropic'` (always `https://api.anthropic.com/v1`, ignores ambient `ANTHROPIC_BASE_URL`; model `claude-*`, optional) or `'openai-compatible'` (`base_url` + `model` required; `@ai-sdk/openai-compatible`). Migration `0002_user_ai_base_url` adds `base_url text null`.
- **Base URL rules** (`src/agents/base-url.ts`): http(s) only, no credentials/fragment. Production: https, public hosts only (rejects localhost, `*.local`/`*.internal`, single-label names, loopback/private/link-local/CGNAT/ULA IPs incl. encoded forms; DNS results re-checked). Development: localhost/private allowed, and `apiKey` is optional for a local endpoint (Ollama). Requests don't follow redirects.
- **Structured output** on OpenAI-compatible: `generateObject` with `json_schema`; on 400/415/422/501, a 404 about unsupported parameters (OpenRouter), or unparseable output → (JSON pulled from the ignored-format answer if possible, else) `generateText` with the JSON Schema in the system prompt, parsed + zod-validated (`src/agents/json-text.ts`). Endpoints that fail `json_schema` are remembered per process and go straight to JSON-in-text. Anthropic-only provider options (`effort`, `structuredOutputMode`) are sent only to Anthropic.
- Behaviour without a key:
  - Buyer chat: assistant replies with a `status` card (tone warning) "Add your AI API key in Settings to use your agent." plus card field `action: {label:'Open settings', href:'/settings'}` (extend the status card schema with optional `action`).
  - Seller agent: skips the request; posts one warning status message in the seller's chat per request-free period (don't spam: at most once per hour).
  - Buyer analysis job: uses the buyer's key; if the key was removed meanwhile, posts the warning card.
- `/api/status → {paypal: 'configured'|'missing', channel3: 'configured'|'missing', ai: 'configured'|'missing'}` (ai = for the current user; `paypal` is also the payments status — payments are PayPal sandbox only).
- **OpenRouter** (recommended, default preset in Settings; free `:free` models): requests to `openrouter.ai` carry `HTTP-Referer: APP_URL` and `X-Title: OpenQuote`. A 429 at validation still saves the key.
- **Rate limits / frugality** (`src/agents/llm.ts`): LLM calls are queued per user (1 at a time for OpenAI-compatible, 2 for Anthropic). HTTP 429 → up to 2 retries honouring `Retry-After` / `retry-after-ms` / `x-ratelimit-reset` (else 4 s, 10 s backoff); a requested wait over 20 s fails at once. The final error text is "AI provider rate limit reached — try again in a minute." LLM calls kept: buyer intake, buyer offer assessment (once per offer; re-scores reuse it), recommendation text, buyer chat Q&A, seller offer decision (one call: picks the product and price), seller counter reply, seller product extraction. Deterministic: seller product pre-filter (keywords/category, `src/agents/seller/match.ts`), buyer counters (`planCounters`), buyer answers to seller questions (from the spec), seller "how are my deals?" summary.

## Removing fabricated data
- **BACKEND (agents):** no pre-loading scripts, `/api/dev/*`, persona-driven fake sellers or templated stand-in replies — agent judgement goes through the user's LLM. Keep deterministic code that is real logic (score formula, policy checks, flags, the frugal steps listed above). Seller agents run only for real seller users with active products and auto_deal on, using **each seller's own key**. LLM errors: retry once (429: see above), then post a clear error status message (no fake fallback).
- **PAYMENTS+INTEGRATIONS:** PayPal sandbox is the only payment path (no fake pay/vault endpoints, no fake onboarding, no `PAYMENT_MODE`; the seller must have a PayPal merchant id to be paid — always). If PayPal env is missing: approve/orders/vault/onboard routes return 503 `{error:'PayPal is not configured on this server'}`. Migration `0003_drop_unused_columns` drops the unused `seller_profiles.persona`/`is_seeded` columns and clears placeholder vault/merchant ids left by an earlier build. Channel3: no generated listings; if no key, `searchMarket` returns [] and the analysis states "Public-web comparison unavailable (Channel3 not configured)". Shopify: only real store connections.
- **FRONTEND:** new `/settings` page (both roles; link in sidebar) with "AI provider" section: key input (password field), model select, Save/Test/Remove, shows last4. Buyer settings + seller settings pages link to it or are merged under /settings tabs. No stand-in checkout sheets or labels; status chips show configured/missing. Handle 503 "not configured" errors and the new status card `action`. No sample-account or sample-store hints. Home example prompts may stay as clickable suggestions (they're UI text, not data). Empty states must read well for a brand-new instance (no sellers yet → "No sellers have joined yet").
